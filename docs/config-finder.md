# Windows 配置查找（v0.2.6）

默认/记忆路径无法读取时，在首次模型检测后使用独立的 `buddy-config-finder` 会话查找。原生 glob、list 和跨目录枚举直接允许，其余操作要求审批，由独立权限监视器一律拒绝；不批准读取文件内容、执行命令、写文件及网络工具。配置内容由宿主程序本地验证，不发送给模型。

只接纳已完成 glob 工具的输出路径，不接纳模型正文中的路径。候选必须是有效 models.json，且路径含 WorkBuddy 目录或条目符合自定义模型特征；其他软件的空数组不自动接纳。单一候选记住并导入；多个候选通过导入按钮选择。托盘提供重新查找和手动选择入口。目录命名或内容特征只能帮助识别，不能证明某个备份就是当前客户端使用的配置；查找不保证枚举完整。

模型失败时尝试其他可用、支持工具的免费模型；取消/退出后终止并删除查找会话。模型上游错误与未找到候选分开记录。已有有效旧配置时不会自动识别它是否已被 WorkBuddy 弃用，可通过托盘重新查找。

2026-10-05 验证：本机 101 项自动测试通过；真实 OpenCode 1.18.34 + Big Pickle 找到临时隐藏 `.workbuddy/models.json`，读取和写入权限未批准。最初使用 `* deny` 精简工具声明的版本返回 403；对照测试保留 `* ask` 原生工具声明成功，所以最终实现保留声明、逐项拒绝非搜索审批。此结论来自对照实测，不代表上游接口规则的承诺。

Windows 以独立目录测试/打包，不覆盖用户工作区；尚未在反馈用户的迁移目录上验收。文件搜索返回的路径不保证是当前生效的唯一配置，已有旧文件仍有效时可从托盘重新查找。
